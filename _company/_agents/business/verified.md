# 💼 현빈 — 검증된 지식

_Self-RAG가 출력에서 `[근거: ...]` 태그가 붙은 주장만 자동 승격해서 누적._
_여기 들어온 내용만 다음 사이클의 retrieval 우선순위에 들어갑니다._
_사용자가 직접 줄을 지우면 그 주장은 다시 미검증 상태로 돌아갑니다._


- [2026-05-18] CEO 지시사항과 핵심 목표를 바탕으로, JY_edu의 MVP 범위 정의 및 초기 비즈니스 전략 초안을 수립하겠습니다. _(근거: 공동 목표, 개인 목표)_
- [2026-05-18] MVP의 목표는 **'최소한의 노력으로 가장 중요한 가치(학생부 평가서 자동 생성)를 제공하여, 첫 유료 사용자 확보 가능성을 검증하는 것'**입니다. _(근거: 개인 목표 - 수익화 모델 1개 가설 검증)_
- [2026-05-18] | **Must-Have** | **① 활동 결과물 업로드 & 입력 폼** | 교사가 학생의 '활동 결과물' 파일(PDF, DOCX 등) 또는 핵심 요약을 직접 붙여넣을 수 있는 UI. (파일 파싱 로직은 최소화, 텍스트 입력 우선) | P0 | 데이터 확보의 시작점. | _(근거: 공동 목표)_
- [2026-05-18] | **Must-Have** | **③ 자동 평가서 생성 엔진 (핵심)** | **[Writer]가 정의한 프롬프트 템플릿 사용.** ①, ②의 데이터를 받아 LLM을 호출하여 '학생부 서술형 평가 보고서'를 출력하는 기능. | P0 | 제품의 존재 이유(Value Proposition). | _(근거: Writer 산출물)_
- [2026-05-18] | **Must-Have** | **④ 교과/활동 태그 지정** | 활동에 해당하는 **교과목 이름** 및 간단한 **활동 키워드 태그**를 수동으로 입력하는 기능. (복잡한 매칭 로직 제외) | P1 | 평가서의 전문성과 맥락 부여. | _(근거: 공동 목표)_
- [2026-05-18] | **Should-Have** | **⑤ 이전 활동 연계 검토 (Basic)** | 학생 ID 기준으로 과거에 제출된 기록이 있을 경우, 해당 기록 목록을 보여주고 교사가 수동으로 '연관성 판단 여부' 체크할 수 있는 기능. (AI 자동 비교 로직 제외) | P2 | 차별화 요소의 초기 맛보기 제공. | _(근거: 공동 목표)_
- [2026-05-18] 초기에는 가치 검증(Validation)이 최우선이며, **'사용량 기반 구독 모델'**을 제안합니다. _(근거: 개인 목표 - 장기 목표)_
- [2026-05-18] 현재 단계에서 **가장 먼저 집중해야 할 것은 P0 기능(Must-Have)**을 완벽하게 구현하여, 교사가 '이것 없이는 안 된다'고 느낄 만한 품질의 평가서를 생성하는 것입니다. _(근거: 개인 목표 - 결정 가능한 권고)_
