### 🚀 JY_edu MVP 범위 정의 및 초기 비즈니스 전략 (초안)

#### 1. MVP 핵심 기능 정의 (Target Audience: 교사)

MVP의 목표는 **'최소한의 노력으로 가장 중요한 가치(학생부 평가서 자동 생성)를 제공하여, 첫 유료 사용자 확보 가능성을 검증하는 것'**입니다. [근거: 개인 목표 - 수익화 모델 1개 가설 검증]

| 구분 | 기능 명 (Feature Name) | 상세 설명 및 범위 정의 | 우선순위 | 근거/필요성 |
| :--- | :--- | :--- | :--- | :--- |
| **Must-Have** | **① 활동 결과물 업로드 & 입력 폼** | 교사가 학생의 '활동 결과물' 파일(PDF, DOCX 등) 또는 핵심 요약을 직접 붙여넣을 수 있는 UI. (파일 파싱 로직은 최소화, 텍스트 입력 우선) [근거: 공동 목표] | P0 | 데이터 확보의 시작점. |
| **Must-Have** | **② 학생 소감문/성찰 기록 입력** | 교사가 학생이 작성한 '소감문'을 텍스트로 입력받는 필드 제공. | P0 | 평가서에 반드시 필요한 정성적 자료. |
| **Must-Have** | **③ 자동 평가서 생성 엔진 (핵심)** | **[Writer]가 정의한 프롬프트 템플릿 사용.** ①, ②의 데이터를 받아 LLM을 호출하여 '학생부 서술형 평가 보고서'를 출력하는 기능. [근거: Writer 산출물] | P0 | 제품의 존재 이유(Value Proposition). |
| **Must-Have** | **④ 교과/활동 태그 지정** | 활동에 해당하는 **교과목 이름** 및 간단한 **활동 키워드 태그**를 수동으로 입력하는 기능. (복잡한 매칭 로직 제외) [근거: 공동 목표] | P1 | 평가서의 전문성과 맥락 부여. |
| **Should-Have** | **⑤ 이전 활동 연계 검토 (Basic)** | 학생 ID 기준으로 과거에 제출된 기록이 있을 경우, 해당 기록 목록을 보여주고 교사가 수동으로 '연관성 판단 여부' 체크할 수 있는 기능. (AI 자동 비교 로직 제외) [근거: 공동 목표] | P2 | 차별화 요소의 초기 맛보기 제공. |

**⚠️ MVP 제외 항목 (Scope Creep 방지):**
*   복잡한 파일 파싱 및 구조 추출 (OCR/NLP 기반).
*   다수 학생 동시 관리 시스템 (초기에는 교사 1인 기준, 세션 단위로 진행 가정).
*   자동화된 활동 적합성 검증 (AI가 '교과 특성에 맞는 활동인가?'를 자동으로 판단하는 기능).

#### 2. 잠재적 수익화 모델 초안 (Monetization Strategy)

초기에는 가치 검증(Validation)이 최우선이며, **'사용량 기반 구독 모델'**을 제안합니다. [근거: 개인 목표 - 장기 목표]

| 단계 | 모델 명 | 특징 및 가격 책정 기준 (가설) | 타겟/목표 |
| :--- | :--- | :--- | :--- |
| **Phase 1 (MVP)** | **Freemium / Credit System** | 월별 기본 크레딧(예: 5회 평가서 생성) 제공. 초과 시 추가 구매 필요. **(가설 검증 단계)** | 초기 도입 교사 확보 및 사용 패턴 데이터 수집. |
| **Phase 2 (Growth)** | **Tiered Subscription (Pro/Premium)** | **Pro:** 월별 무제한 크레딧 + 이전 활동 연계 검토 기능 활성화. / **Premium:** 팀 공유(교사 그룹) + 대시보드 통계 제공. | 충성도 높은 초기 사용자에게 안정적 ARPU 확보. |
| **Phase 3 (Scale)** | **Institutional Licensing** | 학교/교육청 단위 계약. 다수 학생 데이터 통합 관리 및 API 연동 지원. | 가장 큰 규모의 매출 발생 목표. |

#### 3. 비즈니스 의사결정 권고 (Actionable Recommendation)

현재 단계에서 **가장 먼저 집중해야 할 것은 P0 기능(Must-Have)**을 완벽하게 구현하여, 교사가 '이것 없이는 안 된다'고 느낄 만한 품질의 평가서를 생성하는 것입니다. [근거: 개인 목표 - 결정 가능한 권고]

**💡 최종 권고:** **"MVP는 '완성도 높은 서술형 결과물 1개 생산'에만 집중하고, 모든 복잡한 데이터 연동/분석 로직은 Phase 2 이후로 이관해야 합니다."**
